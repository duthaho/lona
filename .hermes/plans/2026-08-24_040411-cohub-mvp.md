# Cohub MVP Implementation Plan

> **For Hermes:** Implement this plan task-by-task with strict test-driven development and verify each vertical slice before continuing.

**Goal:** Build a private, local-first personal AI coworker control plane that gives Hermes Agent deterministic, resumable workflows plus a responsive dashboard for tasks, runs, approvals, artifacts, and workflow definitions.

**Architecture:** Cohub is a standalone Python package and native Hermes plugin. SQLite owns durable workflow state and an append-only event trace. The deterministic engine owns legal transitions, routing, retries, approvals, checkpoints, and completion; pluggable executors perform individual task steps. A dependency-free HTTP API and static dashboard expose the control plane without duplicating Hermes model, memory, skills, messaging, or tool execution.

**Tech Stack:** Python 3.11+ standard library, SQLite, `unittest`, `http.server`, HTML/CSS/vanilla JavaScript, Hermes native plugin API, GitHub Actions.

---

## Product boundaries

### Included in MVP

- Versioned workflow definitions with immutable published versions and SHA-256 fingerprints.
- Node types: `task`, `decision`, `parallel`, `human`, and `end`.
- JSON-object output contracts with required properties and primitive type validation.
- Deterministic route validation: a decision can only select a declared edge.
- Durable tasks, runs, step attempts, approvals, artifacts, and append-only events.
- Retry, step/run budgets, timeout metadata, pause, resume, and cancel.
- Lease-based step claiming to prevent duplicate workers.
- Side-effect approval payload hashes.
- Local executor for deterministic tests and development.
- Hermes Runs API executor adapter.
- Responsive dashboard: Today, Tasks, Run Detail, Approvals, Workflows, and Artifacts.
- SSE event feed and REST API.
- Hermes tools for workflow validation, start, status, cancel, resume, and approval.
- An end-to-end sample workflow that exercises decision routing, retry, human approval, artifact creation, and restart/resume.

### Explicitly excluded

- Drag-and-drop workflow authoring.
- Marketplace, billing, multi-tenant authentication, public relay, and local model management.
- A second chat or memory implementation.
- Automatic high-risk approvals.
- Arbitrary Python embedded in workflow definitions.

## Security invariants

1. Cohub binds to loopback by default.
2. Non-loopback deployment requires a bearer token and should sit behind Cloudflare Access or Tailscale.
3. Approval records bind to canonical payload SHA-256 hashes.
4. Published workflow versions are immutable.
5. Run state changes and event records commit in one SQLite transaction.
6. SQL parameters are always bound; workflow identifiers never become paths without slug validation.
7. Browser-rendered values use text nodes, not `innerHTML` with untrusted data.
8. Secrets remain in Hermes configuration/environment and are never copied into Cohub SQLite.
9. Side-effect nodes cannot execute without an approved matching payload.
10. Artifact paths are constrained to the configured artifact root.

## Task 4: Implement deterministic engine transitions

**Objective:** Make code—not the LLM—own legal workflow transitions.

**Files:**
- Create: `tests/test_engine.py`
- Create: `cohub/engine.py`

**TDD slices:**
1. Starting a run makes only the start node ready.
2. Completing a task schedules its declared successor.
3. A decision accepts only declared routes.
4. Parallel fans out all branches and converges deterministically.
5. Human nodes create a waiting approval and cannot auto-complete.
6. End completes only when required nodes and artifacts are satisfied.
7. Invalid output schema keeps the step incomplete.
8. Retry respects `max_attempts`; exhaustion fails the run.
9. Step and run budgets prevent infinite loops.
10. Pause/resume/cancel enforce valid state transitions.

**Verification:** `python3 -m unittest tests.test_engine -v`.

## Risks and trade-offs

- **Hermes API availability:** The local executor keeps development deterministic; the Hermes adapter is separately tested against a fake server and enabled only when configured.
- **Stdlib HTTP scalability:** Appropriate for one owner and local-first use; replace with a production ASGI server only after measured need.
- **Parallelism complexity:** MVP schedules parallel branches deterministically but processes them with a bounded worker loop; true concurrent execution can be added without changing persisted semantics.
- **Schema scope:** MVP validates a safe JSON Schema subset. Unsupported keywords fail closed rather than being ignored.
- **Plugin coupling:** Hermes integration uses documented plugin and Runs API surfaces; Cohub core remains executable without importing Hermes.
- **Remote exposure:** Direct public binding is not an MVP deployment mode. Use loopback plus Cloudflare Access/Tailscale.
